## บริบท

D-S6 แก้ปัญหาที่ modal เพิ่มสมาชิกดึงแค่ 100 คนแรกจาก 3,063 คนแล้วกรองฝั่ง client
(ครู 119 คนอาจไม่โผล่เลย) → เปลี่ยนเป็นค้นหาฝั่ง server ผ่าน `/members/search` แล้วค้นเจอครบ 119/119

**แต่ยังเหลือช่องว่างเดิม:** คนที่กดเพิ่มสมาชิก **ไม่เห็นว่าครูคนนี้อยู่ฝ่ายอื่นอยู่แล้วหรือไม่**
→ ครูคนเดียวถูกใส่หลายฝ่ายโดยไม่มีใครตั้งใจ และไม่มีอะไรเตือน

**สภาพฐานตอนนี้ (ตรวจ 2026-08-24):** `academy_groups` 39 แถว · `academy_group_members` **1 แถว** ·
`academy_group_permissions` 0 แถว → ชั้นนี้ยังเป็นโครงเปล่า **ป้ายนี้คือสิ่งที่ทำให้การนำคนเข้าฝ่ายรอบแรกไม่มั่ว**

## แบ่งเป็น 2 shard — สัญญาข้อมูลล็อกไว้ตรงนี้ ทั้งสองฝั่งยึดอันเดียวกัน

`GET /api/academies/{academy}/members/search?with_departments=1`

แต่ละแถวใน `members[]` ได้ฟิลด์เพิ่ม **หนึ่งฟิลด์**:

```json
"department_memberships": [ { "id": 12, "name": "ฝ่ายวิชาการ", "role": "head" } ]
```

- ไม่ส่ง `with_departments` → **response เหมือนเดิมทุกประการ** (ฟิลด์นี้ต้องไม่โผล่)
- คนที่ไม่ได้อยู่ฝ่ายไหนเลย → `[]` (ไม่ใช่ `null`)

## D-S6b-a — backend (codex)

### 1. เพิ่ม opt-in `with_departments` ใน `AcademyMemberController::searchMembers()`

**🔴 ห้ามเพิ่มฟิลด์นี้เข้า `AcademyMemberResource`** — resource ตัวนั้นถูกใช้จากหลาย endpoint ทั่วระบบ
การแขวน relation เพิ่มในนั้นจะลาก query เพิ่มไปทุกหน้าที่เรียกใช้ โดยที่ไม่มีหน้าไหนต้องการเลย
→ ให้ผูกข้อมูลนี้ **เฉพาะใน `searchMembers()` หลังได้ผลลัพธ์ของหน้านั้นมาแล้ว**

### 2. 🔴 ห้ามให้เกิด N+1

หน้าหนึ่งมีได้ถึง 100 แถว (`per_page` capped ที่ 100) → **ห้าม query ต่อสมาชิกหนึ่งคน**
→ เก็บ `user_id` ของทั้งหน้าก่อน แล้วยิง **query เดียว** ด้วย `whereIn` เข้า `academy_group_members`
join `academy_groups` แล้วค่อย map กลับเข้าแต่ละแถว

**เกณฑ์ตรวจ:** claude จะนับจำนวน query ด้วย `DB::enableQueryLog()` — จำนวนต้อง**ไม่เพิ่มตามจำนวนสมาชิก**
(เทียบ 5 คน กับ 50 คน ต้องได้จำนวน query เท่ากัน) เทียบเคียงกฎเดิมของโปรเจคเรื่อง query ที่แตะข้อมูลทั้งโรงเรียน

### 3. 🔴 นับเฉพาะ `type = 'department'` เท่านั้น

`academy_groups` มีหลาย type (`office` สำนัก · `department` ฝ่าย · `section` งาน · `academic_group` กลุ่มสาระ ·
`club` · `committee` · `student_council` ฯลฯ) — **`DepartmentController` ทำงานกับ `type = 'department'` อย่างเดียว**
(ยืนยันแล้วที่บรรทัด 54, 70, 139, 507 ของไฟล์นั้น)

→ ป้ายนี้ต้องนับเฉพาะ `department` เช่นกัน · ถ้านับ `section` หรือ `club` เข้าไปด้วย
ป้ายจะขึ้นว่า "อยู่ฝ่ายอื่นแล้ว" ทั้งที่เขาแค่อยู่ชมรม → **ป้ายที่โกหกแย่กว่าไม่มีป้าย**
· ต้องกรอง `academy_id` ของโรงเรียนนั้นด้วย

### 4. เทสต์ (ยิงผ่าน route จริงด้วย `actingAs($actor,'api')`)

1. **ไม่ส่ง `with_departments`** → response **ต้องไม่มีคีย์ `department_memberships` เลย** (กันการเปลี่ยนสัญญาเดิมของ endpoint ที่หน้าอื่นใช้อยู่)
2. ส่ง `with_departments=1` แล้วคนที่อยู่ฝ่าย → ได้ `id` / `name` / `role` ตรงกับแถวจริง
3. คนที่ไม่อยู่ฝ่ายไหนเลย → `[]`
4. **คนที่อยู่กลุ่ม `type` อื่น (เช่น `club`) ต้องได้ `[]`** — เคสนี้คือทั้งหมดของข้อ 3 ข้างบน
5. **จำนวน query ไม่โตตามจำนวนสมาชิก** — สร้าง 5 คน กับ 50 คน แล้วเทียบ

**ฐานเทสต์: `php artisan test --filter Department` = 21 เทสต์ / 44 assertions ห้ามลดลง** (claude รันยืนยันเอง 2026-08-24)

### ขอบเขต — ห้ามเกินนี้

- **ห้ามแตะ `ui/`** (shard b ทำขนานกันอยู่)
- **ห้ามแตะ `AcademyMemberResource`**
- **ห้ามเปลี่ยนพฤติกรรมเดิมของ `searchMembers()`** ทุก filter ที่มีอยู่ต้องทำงานเหมือนเดิม
- **ห้ามเขียน migration ห้ามแตะ schema ห้ามรัน `php artisan migrate` ทุกรูปแบบ**
- ถ้าเจออย่างอื่นที่คิดว่าเป็นบั๊ก **ให้รายงาน อย่าแก้เอง**

## D-S6b-b — frontend (agy)

ไฟล์เดียว: `ui/pages/academies/[name]/admin/departments/index.vue` (1,161 บรรทัด — **แก้เฉพาะสองจุด**)

### 1. ส่ง `with_departments: 1` ไปกับ query ของ `fetchAvailableMembers()` (~บรรทัด 411)

โครงเดิม:
```ts
const query: Record<string, any> = {
  search: memberSearchQuery.value || undefined,
  status: 2,
  page,
  per_page: 25
}
```
**ห้ามแตะ filter อื่นในนั้น** โดยเฉพาะ `roles` ที่ D-S6 เพิ่งเพิ่มไว้

### 2. ป้ายในรายการผลลัพธ์ (~บรรทัด 1084 เป็นต้นไป)

แต่ละแถวเป็น `<label class="flex items-center gap-4 p-3 …">` ที่มี checkbox + รูป + ชื่อ
→ เพิ่มป้ายเล็ก ๆ ให้คนที่ `member.department_memberships?.length` มากกว่า 0
บอกชื่อฝ่ายที่สังกัดอยู่ · **ยังต้องเลือกได้อยู่** (เป็นการเตือน ไม่ใช่การห้าม — ครูอยู่หลายฝ่ายได้จริง)

### 🔴 กติกา mobile-first (บังคับ)

- **class ที่ไม่มี prefix = สไตล์ของมือถือ** แล้วค่อยใช้ `sm:` `md:` `lg:` เพิ่มเมื่อจอกว้างขึ้น
  ห้ามเขียนแบบ desktop-first เช่น `flex-row md:flex-col` — ต้องเป็น `flex-col md:flex-row`
- **ห้ามใช้ `hidden` ซ่อนป้ายบนมือถือ** — ป้ายนี้คือข้อมูลที่คนกดต้องเห็นก่อนตัดสินใจ
- แถวนี้เป็น flex อยู่แล้ว: รูปกับ checkbox ต้อง `flex-shrink-0`,
  ฝั่งข้อความต้อง `min-w-0 flex-1` + `break-words` (ชื่อฝ่ายภาษาไทยยาวและไม่มีช่องว่าง จะดันแถวพัง)
- ถ้าอยู่หลายฝ่าย ป้ายต้อง **wrap ลงบรรทัดใหม่** ไม่ใช่ดันแถวให้กว้างจนเลื่อนแนวนอน
- touch target ของแถวยังต้อง ≥ 44px · **ตรวจจริงที่ 375px ก่อนเสมอ**

### ขอบเขต — ห้ามเกินนี้

- **ห้ามแตะ `api/`** (shard a ทำขนานกันอยู่)
- **ห้ามแตะไฟล์อื่นใน `ui/`**
- **ห้ามเปลี่ยนตรรกะการกรอง/เลือก/pagination ที่มีอยู่** — งานนี้คือ "แสดงเพิ่ม" ไม่ใช่ "เปลี่ยนพฤติกรรม"
- **ห้ามห้ามเลือกคนที่อยู่ฝ่ายอื่น** — เตือนอย่างเดียว
- งานนี้เป็น add-only เกือบล้วน: **ถ้า `git diff` มีบรรทัดที่ถูกลบโดยไม่ได้สั่ง = ไม่ผ่าน**
