# E-S11c — จอหน่วยเลือกตั้งต้องบอกเป็นภาษาไทยว่าให้รอกี่วินาที

> เขียนโดย claude 2026-08-24 · เมนู #25 · shard c ของ E-S11 · **งานใน `ui/` เท่านั้น**
> อ่านประกอบ: `.agents/school-admin/25-elections.md` **§13.5** (สัญญา 429 ที่ล็อกแล้ว) · **§13.6**

## บริบท

E-S11a (commit `65616794`) ทำให้ backend ตอบ 429 เป็น JSON ไทยพร้อม `retry_after` แล้ว
**แต่จอหน่วยยังไม่รู้จักมัน** — `handleError` ใน `station.vue` เขียนว่า

```ts
const handleError = (e: any) => {
  error.value = e?.data?.message || e?.message || 'เกิดข้อผิดพลาด'
  return null
}
```

ครูจึงเห็นแค่ข้อความเดียวโดยไม่รู้ว่า **ต้องรอนานแค่ไหนถึงจะกดได้อีก** ซึ่งบนแถวที่มีนักเรียนยืนรออยู่
"ไม่รู้ว่าต้องรอเท่าไหร่" กับ "ระบบพัง" แยกกันไม่ออก

## สัญญาที่ backend ส่งจริง (ล็อกแล้ว ห้ามเดาเอง)

```json
{ "success": false, "message": "ระบบกำลังรับคำขอถี่เกินไป กรุณารอสักครู่แล้วลองใหม่", "retry_after": 12 }
```

- HTTP status **429** · header `Retry-After` ก็มีค่าเดียวกัน (วินาที)
- `retry_after` เป็น **integer วินาที** และรับประกันว่าไม่เป็น 0 ตอนโดน throttle จริง

## งานที่ต้องทำ (ไฟล์เดียว + i18n)

`ui/pages/academies/[name]/elections/[id]/station.vue`

### 1. ให้ `handleError` แยกเคส 429 ออกมา

- ตรวจ status ให้ครบทุกทางที่ `useApi` โยนออกมาได้ — `e?.statusCode` · `e?.status` · `e?.response?.status`
  (ในไฟล์นี้มีที่ที่เช็ค 404 อยู่แล้วใน `refresh()` ใช้เป็นแบบได้ว่าโปรเจคนี้อ่าน field ไหน)
- ถ้าเป็น 429 → เก็บ `retry_after` ไว้ในตัวนับถอยหลัง แล้วแสดงข้อความจาก i18n **ไม่ใช่จาก `e.data.message` ดิบ**
- ถ้าไม่ใช่ 429 → พฤติกรรมเดิมทุกอย่าง **ห้ามเปลี่ยน**

### 2. ตัวนับถอยหลัง

- ลดลงวินาทีละ 1 จนถึง 0 แล้วเคลียร์แบนเนอร์เอง
- **🔴 ห้ามใช้ตัวแปร `timer` ที่มีอยู่แล้วในไฟล์** — ตัวนั้นเป็นนาฬิกาหมดอายุบัตร (`seconds`) ของโหมด ballot
  ถ้าใช้ร่วมกันจะไปหยุดนาฬิกาบัตรของผู้มาใช้สิทธิ์ที่กำลังลงคะแนนอยู่ → **ใช้ interval ตัวใหม่แยกต่างหาก**
- **ต้อง `clearInterval` ทั้งตอน unmount และตอนตั้งค่าใหม่** ไม่งั้นยิงชนกันหลายตัว

### 3. แบนเนอร์ที่มีอยู่แล้ว

แบนเนอร์ `<p v-if="error" class="fixed bottom-4 left-4 right-4 ...">` ท้ายไฟล์คือที่แสดงผล —
ให้ขยายเป็นกล่องที่มี **ข้อความ + วินาทีที่เหลือ + ปุ่มปิด**

**ปุ่มเป็น "ปิด" ไม่ใช่ "ลองใหม่"** — แบนเนอร์ตัวนี้ใช้ร่วมกันจากทุกฟังก์ชันในหน้า (มี `handleError` ถูกเรียก
จาก 8 จุด) มันจึง **ไม่รู้ว่าต้องยิงอะไรซ้ำ** · ปุ่มลองใหม่ที่เดาเอาเองจะยิงผิดคำสั่ง และในหน้านี้
การกระทำถัดไปเป็นการสแกนบัตรใบใหม่อยู่แล้ว → บอกเวลาที่เหลือให้ครบพอ **ห้ามสร้าง auto-retry**

### 4. i18n — เพิ่มคีย์ทั้ง `th.json` และ `en.json`

ใต้ `elections.station` (บรรทัด 268 ของทั้งสองไฟล์ · **เป็น JSON บรรทัดเดียว ระวังตอนแก้**)

- คีย์ข้อความ 429 (ไทยให้ตรงกับที่ backend ส่ง)
- คีย์นับถอยหลัง แบบมีตัวแปร เช่น `"ลองใหม่ได้ใน {seconds} วินาที"`
- คีย์ปุ่มปิด (ถ้าไม่มี `common.close` อยู่แล้วให้ใช้ของเดิม อย่าสร้างซ้ำ)

## 🔴 กติกา mobile-first (บังคับ — จอหน่วยคือมือถือ/แท็บเล็ตของครู ไม่ใช่เดสก์ท็อป)

- **class ที่ไม่มี prefix = สไตล์ของมือถือ** แล้วค่อยใช้ `sm:` `md:` `lg:` เพิ่มเมื่อจอกว้างขึ้น
  ห้ามเขียนแบบ desktop-first เช่น `flex-row md:flex-col` — ต้องเป็น `flex-col md:flex-row`
- **ห้ามใช้ `hidden` ซ่อนตัวเลขนับถอยหลังบนมือถือ** — มันคือข้อมูลสำคัญที่สุดของแบนเนอร์นี้
- **touch target ขั้นต่ำ 44px** (`min-h-[44px]`) — ปุ่มปิดต้องกดติดตอนครูรีบ
- แถวที่เป็น flex ต้องกัน layout พัง: ฝั่งที่ห้ามถูกบีบใส่ `flex-shrink-0` + `whitespace-nowrap`,
  ฝั่งข้อความใส่ `min-w-0 flex-1` + `break-words` (ภาษาไทยไม่มีช่องว่าง จะแตกเป็นแนวตั้งถ้าโดนบีบ)
- padding/ขนาดตัวอักษรไล่จากเล็กไปใหญ่ เช่น `p-3 sm:p-4`, `text-sm sm:text-base`
- **ตรวจจริงที่ 375px ก่อนเสมอ** แล้วค่อยตรวจ 768px / 1280px
- แบนเนอร์เป็น `fixed bottom-4 left-4 right-4` อยู่แล้ว → ระวังไม่ให้ไปทับแผงยืนยัน
  `fixed inset-x-4 bottom-4` ของโหมด ballot ที่อยู่ตำแหน่งเดียวกัน
