## บริบท — สิ่งที่ตรวจแล้วและสิ่งที่ขาด

E-S11a และ E-S11b **โค้ดทำงานถูกทั้งคู่** claude ตรวจเองแล้วด้วยการรันกับ DB จริงใน transaction แล้ว rollback:

```
BEFORE SWEEP: progress-style live count = 1  (raw status=issued = 2)
expireStaleAll() swept = 1 rows, using 2 queries
stale now: status=expired token_hash=NULL   |   live now: status=issued
turnout keys: voted,total,receipts_total,percentage,by_grade_level,by_station
```

**แต่ E-S11b ไม่ได้เขียนเทสต์เลยสักตัว** — ชุดเทสต์ขึ้นจาก 141 เป็น 142 และ +1 ตัวนั้นเป็นของ E-S11a
สิ่งที่ยืนยันแล้วข้างบนจึงไม่มีอะไรกันไม่ให้พังในอนาคต · งานรอบนี้คือ **เข้ารหัสสิ่งที่พิสูจน์ด้วยมือไปแล้วให้เป็นเทสต์**
บวกกับเก็บหนี้เชิงคุณภาพอีก 3 ข้อ

**ฐานปัจจุบัน: 142 เทสต์ / 377 assertions · pint ผ่าน** — ห้ามลดลง และรอบนี้ต้องเพิ่มอย่างน้อย 4 เคส

## A — เทสต์ที่ขาดของฝั่ง E-S11b (สำคัญที่สุดของงานนี้)

เขียนใน `tests/Feature/Election/ElectionStationTest.php` (มีเคส `expireStale` อยู่แล้ว 2 เคส ใช้เป็นแบบได้)
ยกเว้นเคส **B1** ที่ต้องยิงผ่าน route จริง

**B1 — 🔴 เคสชี้ขาด พิสูจน์ข้อตัดสิน §13.3 ข้อ 1**
ใบเสร็จ `status='issued'` ที่ `token_expires_at` เป็นอดีต **และยังไม่รัน `expireStaleAll()` เลย**
→ `GET /{election}/stations/{station}/progress` ต้องคืน `issued = 0` ทันที
ยิงผ่าน route จริงด้วย `actingAs($actor,'api')` **ห้ามเรียก controller ตรง ๆ** (บทเรียน §7.2)
ในเคสเดียวกันให้มีใบเสร็จที่ยังไม่หมดอายุอีกใบ แล้วยืนยันว่านับเป็น 1 ไม่ใช่ 2 — นี่คือสิ่งที่แยก
"นับด้วยเงื่อนไขเวลาสด" ออกจาก "รอ cron มาเปลี่ยน status"

**B2 — `expireStaleAll()` กวาดข้ามการเลือกตั้ง**
สร้างใบเสร็จหมดอายุใน **2 election** แล้วเรียกครั้งเดียว → ต้องกวาดครบทั้งสองฝั่ง
และ `token_hash` ของทุกแถวที่ถูกกวาดต้องเป็น NULL

**B3 — ของที่ห้ามแตะต้องไม่ถูกแตะ**
ใบเสร็จที่ยังไม่หมดอายุ (`token_expires_at` อนาคต) ต้องยังเป็น `issued`
และใบเสร็จ `status='cast'` ต้องไม่ถูกเปลี่ยนเด็ดขาดแม้ `token_expires_at` จะเป็นอดีตแล้วก็ตาม
(เคสหลังนี้สำคัญ — ถ้าพลาดคือคะแนนที่ลงไปแล้วหาย และ invariant §2.3 จะพังตอนปิดหีบ)

**B4 — command เรียกได้จริงและรายงานตัวเลขถูก**
`$this->artisan('elections:expire-stale-receipts')` ต้องจบด้วย exit code 0
และจำนวนที่รายงานต้องตรงกับจำนวนแถวที่หมดอายุจริง

## B — รวบ `expireStaleAll()` ให้เหลือ query เดียว

ตอนนี้เป็น

```php
Election::query()->each(fn (Election $e) => $expired += $this->expireStale($e));
```

→ **1 + N query** (วัดจริงแล้วได้ 2 query ต่อ 1 election) · เป็น scheduled job ที่รันทุก 5 นาที
และ N โตขึ้นทุกครั้งที่สร้างการเลือกตั้งใหม่ ทั้งที่ส่วนใหญ่ไม่มีอะไรให้กวาดเลย

→ เขียนใหม่ให้เป็น **UPDATE เดียว** บน `election_voter_receipts` โดยใช้ predicate ตัวเดิมที่แยกไว้แล้ว
(`staleReceipts()`) ส่งเป็น `ElectionVoterReceipt::query()` เข้าไปแทนที่จะวน election
· `expireStale(Election $e)` **ต้องคงพฤติกรรมและ signature เดิมเป๊ะ** — `closeAndCount()` เรียกมันก่อนตรวจ invariant §2.3
· ทั้งสองเมธอดยังต้องคืน `int` เป็นจำนวนแถวที่กวาดเหมือนเดิม
· เทสต์ B2 คือตัวที่พิสูจน์ว่าการรวบนี้ไม่ทำอะไรพัง

**ใส่ type hint ให้ `staleReceipts()` ด้วย** ตอนนี้รับ `$query` เปล่า ๆ และไม่ประกาศ return type

## C — เทสต์ที่ขาดของฝั่ง E-S11a

เพิ่มใน `tests/Feature/Election/ElectionRateLimitTest.php` (มีอยู่แล้ว 1 เคส ใช้ `context()` เดิมได้)

**A1 — limiter คนละตัวต้องไม่กินโควตากันเอง**
ยิง `/cast` จนเต็มเพดานแล้ว `/issue` ที่หน่วยเดิมต้องยังทำงานได้ตามปกติ
(ยืนยันแล้วว่า Laravel ทำ `md5($limiterName.$limit->key)` ให้ จึงควรผ่าน — เทสต์นี้มีไว้ล็อกพฤติกรรมนั้นไว้
ไม่ให้ใครเผลอเปลี่ยนไปใช้ limiter ร่วมกันทีหลัง)

**อย่าลืม `Cache::flush()` ใน `setUp()`** — ไฟล์นี้มีอยู่แล้ว ถ้าเพิ่มเคสใหม่ต้องแน่ใจว่าไม่กินโควตาข้ามเคสกันเอง

## D — คอมเมนต์เหตุผลของเพดาน (ข้อที่สเปกเดิมสั่งแต่ยังไม่ได้ทำ)

ใน `AppServiceProvider::boot()` เหนือ `RateLimiter::for(...)` ทั้ง 4 บรรทัด ให้เขียนคอมเมนต์สั้น ๆ ว่า
**ทำไมถึงเป็นตัวเลขนี้** — ผู้มีสิทธิ์ 2,193 คน เปิด ~4 หน่วย 3 ชั่วโมง = ~3 คน/นาที/หน่วยโดยเฉลี่ย
แต่ช่วงพักกลางวันกระจุกหนักกว่าค่าเฉลี่ยหลายเท่า → เพดานตั้งไว้กันบอท ไม่ใช่กันแถว
· และเขียนกำกับด้วยว่า **ห้ามเปลี่ยนไปคีย์ด้วย IP** เพราะทุกหน่วยอยู่หลัง NAT เดียวกันของโรงเรียน

## ขอบเขต — ห้ามเกินนี้

- **ห้ามแตะ `ui/`** ทั้งหมด
- **ห้ามเปลี่ยนสัญญา 429** ที่ล็อกไว้แล้วใน §13.5 — shard c (จอ) จะเขียนตามอันนั้น
- **ห้ามเปลี่ยนคีย์ใน payload ของ `progress()` และ `turnout()`** — จัดไปแล้วในรอบก่อน
- **ห้ามแก้ `issue()` / `cast()`**
- **ห้ามรัน migration หรือแตะ schema** · **ห้ามรัน `migrate:fresh`** เด็ดขาด (DB มีนักเรียนจริง 2,931 คน)
- ถ้าเจออย่างอื่นที่คิดว่าเป็นบั๊ก **ให้รายงาน อย่าแก้เอง**
